# Private mobile character editor

The desktop launcher still uses the existing local SQLite database. Mobile access is disabled unless `mobile-access.json` in that same local data directory explicitly enables it. One Node process serves the desktop on loopback 4317 and a restricted editor on loopback 4318; both share the same SQLite connection. Never proxy port 4317 through Tailscale Serve, bind either server to a LAN address, or enable Funnel.

## Setup

1. Install Tailscale on Windows and iOS/iPadOS. Sign into the same personal account. Enable MFA at the identity provider and approve only intended devices.
2. Run `Enable Mobile Access.cmd`. It reads the exact local Tailscale account/DNS name and writes the allowed identity/origin outside OneDrive. It refuses to create a replacement database and does not configure Serve.
3. Restrict the tailnet policy to the intended account/devices connecting to this laptop's HTTPS port 443. Review and remove overlapping broad allow rules: adding a restrictive grant cannot cancel a broader existing grant. Preserve unrelated rules when editing an existing network. Do not enable node sharing or Funnel for this application.
4. Restart the desktop launcher. Confirm the console reports the restricted editor on loopback 4318.
5. After the policy is checked, run `tailscale serve --bg http://127.0.0.1:4318`. Enable MagicDNS/HTTPS if prompted; do not approve public sharing/Funnel. Verify `tailscale serve status` says **Available within your tailnet**, and check the JSON configuration contains no `AllowFunnel: true`.
6. With Tailscale connected on the iPad/iPhone, open the exact HTTPS `.ts.net` address in Safari. A home-screen bookmark is optional. Turn off Wi-Fi on the iPhone once to verify access over cellular. Test a small edit and confirm it appears on the laptop.

Serve uses public HTTPS certificates: the chosen machine hostname appears in certificate transparency logs, while app access remains private. The laptop must remain awake, online, and running both Tailscale and Living Universe. Serve's background setting does not automatically start the Node app. Closing the lid may put Windows to sleep.

## Scope and security

Every mobile request requires the exact configured Tailscale identity, an accepted Host and a loopback peer. Serve strips spoofed identity headers. Local Windows processes are trusted; this does not protect against malware running on the laptop. The app does not trust arbitrary forwarded-host or forwarded-protocol headers. Only the configured HTTPS Origin is permitted for writes, together with JSON, a CSRF token, and cross-site fetch rejection. Authentication failures also protect HTML and scripts. Private responses use no-store and a restrictive CSP. Missing/malformed configuration disables remote access.

The mobile listener has its own explicit routes for text profiles, directed relationships, name-only character creation, location-tag creation, logical image sorting, the user-requested metadata-only file check, and reviewed batch relinking of unique filename matches. Desktop APIs, original media downloads, physical file moves, renames, deletion, exports/restores, arbitrary reconciliation choices and canon approvals are not routed through it. Existing primary names are read-only because desktop name changes can physically rename folders. Administrator notes are visible only to the allowed creator account; they are not fed to any character prompts.

## Mobile image sorting

Open **Képek rendezése** at the same private HTTPS address. **Rendezendő képek** follows the desktop Needs sorting rules; **Összes kép** also includes finished pictures and location references. Search by filename/folder. Pages contain up to 24 pictures; cursor pagination and a fixed page sequence prevent skipping items as completed pictures leave the queue.

Tap a picture, select one or more existing characters, choose an optional existing location, expand the initially closed structured tags, and edit ordinary tags/notes. **Mentés és következő** explicitly completes sorting, including multicharacter pictures. **Mentés későbbre** saves metadata with review still required. Previous/Skip navigate without saving; unsaved choices are kept in this browser's local storage and restored when reopening the image. Offline use is recovery of already opened drafts, not a fully offline library. Reconnect and use Save; successful saves are explicitly confirmed. Browser-storage clearing or eviction can lose drafts.

**Új karakter hozzáadása** is available on the Characters tab and under the image's character picker. The profile contains only the supplied name; other profile fields stay empty. The same action now also ensures a same-named directory in the configured OneDrive resource root, using the shared folder manager. An existing ordinary directory is reused without modifying its contents or assigning its media. Windows-invalid/reserved names, files using the same name, symlinks, location folders and folders owned by another character are refused. The folder-owner mapping and character are recorded together; a failed database save rolls back the record and removes only the operation's own still-empty new directory, never an existing folder or files. If OneDrive/root access fails, creation fails with the name draft retained for retry. Retrying the same request reuses the directory and preserves later profile edits. No automatic backfill, rename or relocation of existing characters is performed.

The profile-tab action opens the new editor. In sorting, the character becomes checked while other choices/notes stay intact; save the image to commit its assignment. Creation uses a browser-retained UUID, authenticated atomic inserts and Unicode-normalized duplicate-name checks.

**Új helyszíncímke hozzáadása** beneath the location dropdown reuses the existing location/structured-tag helper without creating a folder. Repeated normalized names reuse the existing location. The new location and its setting tag become selected; save the image to commit the association. Name drafts survive connection errors in the same browser. Save waits for an in-flight inline creation, so it cannot silently omit a just-created selection. Creation is name-only and follows the same identity, exact-Origin and CSRF protections as other mobile writes.

After changes made directly in OneDrive, use **Fájlok újraellenőrzése**. This explicit, identity/Origin/CSRF-protected action reuses the existing metadata scanner with no caller-supplied paths or destructive options. It detects new/modified/missing/unavailable files and stages possible external moves; it never deletes records or automatically links uncertain matches. Missing/unavailable records are hidden by default in mobile image lists after scanning; **Hiányzó / elérhetetlen képek mutatása** restores their visibility. Their original assignments and IDs stay intact, and reappearing files return after another scan. The summary survives a dropped connection and page reload. The laptop and OneDrive must be running and synchronized; this action does not force OneDrive cloud synchronization or download online-only originals.

**Egyező áthelyezések összekapcsolása…** previews a batch of up to 1,000 one-to-one filename/size/mtime matches, showing the count and up to eight relative old/new locations. This is metadata evidence, not a general claim of identical content. Confirming the exact preview uses an expiring server-side token; the client cannot supply file paths or target IDs. Duplicate names, competing destinations and renamed filenames are excluded and remain for desktop review. Files, source absence, catalogue membership, symlinks and current canonical fingerprints are revalidated. Approved references must be locally available and match every current approved fingerprint. A verified SQLite online backup is created in the local data directory before the entire batch commits atomically. Other app mutations are blocked during preparation/backup/commit. IDs, depictions, canon, reviews, notes and sorting completion remain untouched; existing external-relink journal entries record each changed location. Repeating the same token returns the original result, while stale/expired previews are refused. No physical files are moved or renamed. Backup recovery remains a separately approved action and is never automatic.

All sorting edits use the existing tables and one atomic compare-before-write transaction. Concurrent changes are rejected and displayed alongside the retained draft; the user can load the saved version or retain their draft after comparison, then save explicitly. Retrying an identical saved request is harmless. Existing reviews, canon, stable IDs and originals are untouched; removing an assignment used by current canon is refused. No new database/migration or network exposure is required.

Preview URLs accept only active image catalogue IDs. Originals are read only after containment, symlink, source-size and local OneDrive availability checks. JPEG previews are bounded to 768 pixels and 192 KiB, with two conversions at a time and a bounded in-memory cache. Preview generation uses the existing Windows decoder; unsupported formats display an error and Retry without changing the record. Online-only files must be made available on the laptop first. Videos, location-folder creation, bulk sorting operations and physical file management remain in the desktop application.

Fields save after a short pause or leaving the field, with explicit Save controls. Drafts are saved in that device/browser's origin-scoped storage while typing. They include the original saved text for conflict detection. Browser storage is a recovery aid, not a synced database or guaranteed backup: clearing website data, storage eviction or losing the device can lose drafts. Safari must first load the application while the laptop is reachable; this prototype is not an offline-installed PWA. The UI reports storage failures instead of claiming a draft is safely retained.

Profile updates compare original values in an atomic SQLite transaction. Relationship writes compare the original description. Conflicts preserve drafts and show the latest version with explicit choices; they never automatically replace it. Supported desktop editor requests also send their original values, with compatibility retained for older callers. Do not use old cached desktop tabs for concurrent editing; refresh them after upgrading.

## Disable and rollback

Stop the app, set `enabled` to `false` in the external mobile configuration (or remove that configuration), then restart. Disable only the relevant Serve mapping with `tailscale serve --https=443 off` after checking it is not used by another service. No database migration or database replacement is involved. Drafts stay on each Apple device until saved/cleared. Keep normal restorable catalogue backups separately; a backup should never be automatically restored by this setup.
