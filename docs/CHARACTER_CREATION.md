# Sorting Window character creation

The inline Create new character form offers a Suggest name button beside its free-text name input. It fills the input without creating a character or changing gender. Create & select character remains the explicit save action; the media assignment is saved separately with the existing sorting controls.

The selected race controls the name pool. Human suggestions are Hungarian male given names with their accents, without family names. Each of the eleven fantasy categories has a separate pool built from the creator's examples and matching sound patterns: guttural Orcs, short/sibilant Goblins, rumbling Trolls, mythological Minotaurs, rhythmic Centaurs, woodland Satyrs/Fauns, rough Werewolves, hissing Lizardfolk/Dragonborn, sturdy Dwarves, simple/heavy Ogres and weighty Bearfolk/Bullfolk. No external AI provider is called.

Every request reads current character names from the database, including merged records and characters of other races. Comparison removes Unicode combining accents, folds case, trims leading/trailing whitespace and collapses repeated whitespace. The form keeps a session-local suggestion history. After showing every available candidate in the selected pool, another round avoids the current input where possible. Exhaustion and errors leave the input editable; an exhausted fantasy pool never falls back to human names. A manual edit made during a pending request takes precedence. Changing Race immediately requests and fills a matching new name, without requiring a Suggest name click. Rapid race changes supersede earlier requests, whose responses and errors cannot overwrite the latest selection or re-enable saving prematurely. Manual edits made while waiting are preserved.

Race defaults to Human and offers the eleven requested grouped categories in English. Stable API values are human, orc, goblin, troll, minotaur, centaur, satyr_faun, werewolf, lizardfolk_dragonborn, dwarf, ogre and bearfolk_bullfolk. Race can be viewed and changed in the desktop character profile; changes autosave and use the existing conflict checks. It is returned by the desktop API and MCP character details, and included in catalogue exports. Other creation paths inherit Human from the database default.

Migration 022 adds a constrained non-null column with a Human default. Existing rows retain all other values. Before altering an existing populated catalogue, startup creates and verifies an online SQLite backup in the local catalogue's backups directory. Old exports without race restore as Human; old clients omitting race on update preserve the saved race. The down migration requires a backup and reverting race-aware code first.

Limits: suggestions use a finite local vocabulary, not an AI provider; they are checked at suggestion time and do not reserve a name against concurrent creation. Manual names remain allowed. The Human legacy default is a compatibility value, not a claim inferred from character images or biographies. Race editing is exposed in the desktop profile; the separate mobile editor has no new race control.

Verification: focused tests cover Hungarian given names, all race-specific example sets and generated pools, database collisions across races, normalization, session reuse, exhaustion, manual-edit/error handling, changing race during a pending request, migration backup, validation, conflict protection, restart, MCP reads and old/new restores. Browser verification also covers explicit character creation, retained sorting notes and assignment/completion.
